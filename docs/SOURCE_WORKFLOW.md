# Source Workflow — 来源工作流

## 1. 先建来源，再写文章

新主题先创建：

`source/<分类>/<主题>/index.json`

本仓库历史目录实际使用 `sources/`，因此当前统一写为：

`sources/<分类>/<主题>/index.json`

推荐结构：

```json
{
  "topic": "主题",
  "last_checked": "2026-08-28",
  "sources": [
    {
      "id": "S1",
      "title": "标题",
      "publisher": "机构/媒体",
      "date": "YYYY-MM-DD",
      "url": "https://...",
      "tier": "A",
      "type": "primary|reporting|paper|dataset|company|union",
      "status": "live",
      "supports": ["C1", "C2"]
    }
  ]
}
```

## 2. 版权与归档

旧体例曾要求把重要网页整页保存到 `sources/`。这在实践中既难维护，也可能不适合受版权保护的新闻页面。

从本版本起：

- 默认保存**来源元数据、URL、日期、标题、证据等级、支持的 claim id**；
- 政府文件、工会协议、公开数据集等允许且必要时可保存公开原文或下载件；
- 新闻报道不复制整篇正文，只保留必要摘要和极短引文；
- 若 URL 失效，标记 `dead`，并记录可合法访问的归档地址或替代来源。

## 3. 来源优先级

A：原始合同、集体协议、政府统计、论文、法院文件、官方数据。

B：有采编责任的调查报道与新闻机构。

C：研究机构解释文、行业报告、可靠二手材料。

D：个人帖子、论坛、未核实截图，只用作线索。

## 4. 链接检查

每次大修应：

- 检查 README 中所有相对路径；
- 检查新文章的所有外链；
- 对 404/重定向/标题变化进行记录；
- 不因链接失效直接删掉历史事实，而应寻找替代来源并标注来源迁移。

## 5. 更新频率

- 快速变化：裁员、公司组织调整、平台工资、估值、合同谈判——3 至 6 个月复核；
- 中速变化：行业就业结构、政策——6 至 12 个月复核；
- 历史案例：来源不变时按需复核。

## 6. 反证也要归档

如果一个来源显示“总体就业尚未出现大规模崩溃”，即使它削弱仓库原有叙事，也必须收录。史料库的目标是保留现实，而不是保卫预设结论。
